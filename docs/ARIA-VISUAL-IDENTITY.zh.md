# Aria 视觉识别与界面原型

[English](ARIA-VISUAL-IDENTITY.md) | 中文

Aria 是对 DeepSeek Harness（DSH）客户端界面的品牌重塑：同一套运营软件——会话、智能体、工具、知识、审批——以新的识别系统呈现，并按 *任务* 而非对话重新组织。本文档记录 `packages/aria/` 中原型的品牌、设计系统、信息架构、六个界面、交互模型以及验证证据。它面向两类读者：评审这项工作的人，以及将要把界面接入真实服务的人。

**原型是前端，不是产品。** 它渲染演示数据，只修改组件本地状态，不调用任何服务。`packages/aria/` 中的任何内容都不涉及认证、数据库结构、智能体定义、模型路由、记忆基础设施或任何后端包。

## DSH 界面是什么，原型对它做了什么

参照物是 DSH Web 客户端：`apps/web` 渲染 React 应用，`packages/client/ui-layout/src/client/AppFrame.tsx` 拥有三栏框架（侧边栏 | 中栏 | 右栏），`packages/client/ui-primitives` 提供设计系统原子组件。该客户端以对话为核心：侧边栏列出会话，中栏是带输入框的对话记录，右栏承载上下文面板。它的视觉语言是偏蓝的深色中性主题（`packages/client/ui-theme/src/styles/design-platform.css`），由 `--dsw-*` 语义别名驱动每个组件。

Aria 保留这套架构，改变三件事。它把导航从会话列表重组为五个运营区域加设置；它把工作单元从 *对话* 重新定义为带显式计划、评审闸门与产物记录的 *任务*；它把外壳重绘为源自需求品牌值的石墨色加荧光青柠配色。为此没有修改任何 DSH 包。原型逐个使用 `ui-primitives` 原子组件，只在自身子树内叠加 Aria 令牌层；即使两者同时挂载，原版客户端也保持像素一致。

## 品牌识别

性格需求是智能、精确、可靠、克制、技术成熟。每一条都对应一个决策，而不是一个形容词：

| 价值 | 决策 |
| --- | --- |
| 智能 | 一个由顶点与两条收束笔画构成的几何标记，可读作字母 *A*，也可读作一扇拱门。没有任何装饰与之争夺注意力。 |
| 精确 | 一个强调色、一套笔画粗细（24 单位网格上 1.6）、一套圆角阶梯、以细线代替阴影。 |
| 可靠 | 界面在每条记录上都标明时间、状态与归属；没有来源的数字不出现。 |
| 克制 | 石墨色底面、低彩度次级文字，没有辉光、渐变或霓虹铺陈。青柠色只出现在 Aria 请求注意或确认操作的位置。 |
| 技术成熟 | 经典比例——收窄的塔身、平截的顶端、横贯拱门的楣线——而非对某段历史风格的直接引用。 |

成品刻意克制。为显得"高级"而做的原型往往诉诸渐变与辉光；这一版诉诸比例、间距与节制，而这正是参照品牌值所描述的东西。

### 标记

符号是 24 单位网格上的单一抽象形，由三部分组成：

- **拱门**——一个窄四边形，底部最宽、顶部平截：`M10.6 2.7H13.4L19.2 21.3H4.8Z`。平截的顶端很关键。更早的一版把形状收成尖顶，立刻被读成房屋图标；截平顶端既保持建筑感，又不至于指认某座建筑。
- **楣线**——`M7.6 14.4H16.4` 处的一条横线，比主体细一档。它像门楣一样横跨洞口，是标记中唯一的内部线条。
- **转角**——`linecap: square` 与 `linejoin: miter`。圆头端点会把形状软化得比品牌允许的更亲和。

底板色调用 `--aria-lime-400` 填充圆角方，并以 `--aria-lime-ink` 绘制标记；描边色调则以 `currentColor` 描出底板并用同色绘制标记，标记落在墨色底面上时即采用后者。16px 及以下时笔画从 1.75 加粗到 2.3，使开口保持通透；楣线在两种情况下都保持主体粗细的 0.86 倍（在底板变体中同一阈值下为 `2.15`）。几何构造以 `ARIA_MARK_GEOMETRY` 导出，未来图标流水线可据此在任意尺寸上重建同一形状。

### 字标

字标以 Montserrat 500 字重排 **Aria.**，句点使用 `--aria-lime-400`。句点是唯一着色的元素：它是标记的句读，是"句子已完成"的断言。全大写形式 **ARIA.** 使用 400 字重与 `letter-spacing: 0.19em`，是产品名需作为专有名词而非声音阅读时使用的机构变体。

最初尝试过手绘字母轮廓，随后放弃。为四个字母手工描出的轮廓在任何尺寸下都显得业余；用仓库已随附的字型排印名称既更可信也更易维护，同时让标记成为整套识别中唯一的定制绘制。

### 四种品牌变体

| 变体 | 组件 | 用途 |
| --- | --- | --- |
| 主字标 | `AriaWordmark`、`AriaLockup` | 页头、文档，以及任何有空间容纳名称与标语 `OPERATIONAL INTELLIGENCE` 的位置。 |
| 紧凑符号 | `AriaSymbol` | 导航栏头部、网站图标，以及任何 32px 以下的方形位。底板为内缩 0.6、圆角 5.4、描边 1.1 的 24 单位矩形。 |

四种变体都是 SVG，在上述尺寸下都可辨认，且都由同一组几何常量绘制。参见 `docs/assets/aria/brand-sheet.png` 中的品牌图版。

## 色彩

需求给定的色板按规格使用，只做为了对比度以及与原型复用的 DSH 原子组件保持一致所必需的最小调整。

| 令牌 | 值 | 角色 |
| --- | --- | --- |
| `--aria-bg-canvas` | `#0b0e0c` | 页面底色（`aria-ink-950`）。 |
| `--aria-bg-surface` | `#121713` | 卡片、面板、抽屉主体（`aria-ink-850`）。 |
| `--aria-bg-elevated` | `#181f19` | 嵌套凹槽、标签、悬停行（`aria-ink-800`）。 |
| `--aria-bg-raised` | `#1d251e` | 选中行、菜单、提示条底色（`aria-ink-750`）。 |
| `--aria-border-subtle` | `#273128` | 所有细线（`aria-line-900`）。 |
| `--aria-text-primary` | `#f1f5ee` | 标题与记录名（`aria-text-100`）。 |
| `--aria-text-secondary` | `#9aa59a` | 辅助文案与元数据（`aria-text-500`）。 |
| `--aria-lime-400` | `#c8f169` | 强调色。 |

组件从不直接读取调色板档位。每个组件消费的是语义角色——`--aria-bg-surface`、`--aria-text-secondary`、`--aria-status-waiting`——调色板位于下一层，这正是改动一个令牌只需改一行的原因。

两项决策扩展了需求。第一，文字阶梯需要中间档：仅有 `#f1f5ee` 与 `#9aa59a` 无法表达五级层次，因此在两者之上、之间与之下增加了档位（`text-050` 至 `text-700`）。最暗的一档 `text-700` 只用于仅作为质感被阅读的标签。第二，每种状态色都需要一个可读的文字变体：`amber-300`、`red-300`、`blue-300` 是用于着色状态填充内部的文字档，因为 400 档作为圆点与描边可达标，但作为着色底上的小字则过于贴近 4.5:1 的界线。

强调色是有意使用而非四处点缀：主按钮、选中的导航竖条、运行状态圆点与进度线、步骤标记、"进行中"标签、问候语分隔线以及字标中的句点都取 `lime-400`，另有多处表面用 `color-mix` 把它调向底色。克制体现在每个元素上的用量而非元素的数量——6% 至 16% 的混色读作暖黑，满强度的强调色只出现在 1px 宽的线或陈述状态的标签上。渐变极少：仅两处，都在总览横幅内，一处是 6% 透明度的淡抹，一处是标记问候分隔线的强调色淡出。它们是界面中唯一沿某个轴向变化的颜色。系统的一处高度阴影是抽屉左缘；其余每处 `box-shadow` 都是 1px 内嵌环或 3px 状态光晕。

## 字体排印

界面复用仓库已随附的字体——展示用的 Montserrat 与界面用的系统 UI 字族——而不新增网络字体依赖。字阶共八级，每个界面只使用这些：

| 令牌 | 字号 / 行高 | 用途 |
| --- | --- | --- |
| `--aria-text-2xl` | 30 / 36 | 每个界面的页面标题。 |
| `--aria-text-xl` | 22 / 28 | 抽屉标题与总览横幅主标题。 |
| `--aria-text-lg` | 17 / 24 | 区块标题。 |
| `--aria-text-md` | 14 / 22 | 卡片标题与强调正文。 |
| `--aria-text-base` | 13 / 20 | 正文、记录名、散文。 |
| `--aria-text-sm` | 12 / 18 | 卡片元数据、列表行、控件。 |
| `--aria-text-xs` | 11 / 16 | 记录下方的辅助行。 |
| `--aria-text-2xs` | 10 / 14 | 步骤耗时、表格说明、大写标签。 |

字阶伴随三个字距值：`--aria-tracking-display`（0.02em）用于识别性文字，`--aria-tracking-label`（0.08em）用于大写眉标与状态标签，`--aria-tracking-data`（0.01em）用于数字。字重来自四个令牌——`--aria-weight-light` 300、`regular` 400、`medium` 500、`semibold` 600——没有任何组件使用这四者之外的粗细。

凡是会变化的数字都使用等宽数字（`font-variant-numeric: tabular-nums`），因此一个进度百分比不会推动它所在的行。等宽字族专用于标识符——任务与智能体 id、模型名、事件日志中的时间戳——即读者需要字符对齐的地方。

## 设计令牌

令牌层位于 `packages/aria/theme/src/css/tokens.css`，并以数据形式镜像于 `tokens.ts`。

- **间距**——4px 节奏：`--aria-space-1` 至 `--aria-space-10`（4、8、12、16、20、24、32、40、48、64）。界面由这些值组合而成，从不硬编码像素间隙。
- **圆角**——`xs` 3px、`sm` 6px、`md` 10px、`lg` 14px、`panel` 18px、`pill` 999px。卡片用 `md`，面板用 `panel`，标签用 `xs`，控件用 `sm`。偏方的阶梯是刻意的：大而柔的圆角会软化一个以精确为基石的品牌。
- **描边**——每个边界都是来自 `--aria-line-900` 的 1px（`--aria-hairline`）细线；较重的 `--aria-line-800` 只出现在交互控件与选中行上。
- **高度**——四个令牌，全部是 1px 描边加低透明度环境阴影：`hairline`、`card`、`raised`、`overlay`。没有辉光，也没有彩色阴影，因此青柠强调色从不变成光。
- **控件**——三个共享高度，`--aria-control-sm` 28px、`md` 34px、`lg` 40px，使按钮、输入框与筛选标签在同一行对齐。
- **动效**——三条时长（`fast` 90ms、`base` 160ms、`slow` 260ms）共用一条缓动曲线（`--aria-ease`），关闭使用 `--aria-ease-exit`。所有过渡在 `prefers-reduced-motion` 下关闭。

由于抽屉与模态框被传送（portal）到 `document.body`，原型在挂载期间为 `<body>` 添加 `aria-surface`，并在卸载时移除。若没有该 class，浮层会以 DSH 默认配色绘制——第一次集成截图暴露的正是这个缺陷。

`components/primitives.tsx` 是通向 `ui-primitives` 的唯一接缝：每个界面都经由它导入原子组件，因此复用控件的清单是一个文件，而不是一次全库检索。在其之下，`src/atoms.ts` 直接从源码文件导入这些原子与符号，而不经由包的总出口——总出口还再导出了 markdown、diff 与语法高亮模块，其第三方依赖在源码模式检出中未必安装，而原型一个都不渲染。正是这一层间接，使预览与测试无需构建步骤、也不依赖总出口。

## 信息架构

主导航按一天工作的阅读顺序排列五个目的地——**Overview**（总览）、**Missions**（任务）、**Agents**（智能体）、**Knowledge**（知识）、**Activity**（活动）——**Settings**（设置）单独归入导航栏底部的一个次级分组。导航栏在 Missions 项上标注等待决策的任务数量，因为那是唯一要求操作者采取行动的计数。

路由由 `routes.ts` 以哈希方式拥有：`#/missions?mission=mis-vendor-diligence` 打开任务登记册并同时展开该任务的抽屉，因此详情视图可被链接并在刷新后保持。未知路由回退到总览。

六个界面按顺序回答六个问题：

1. **总览**——正在运行什么、什么需要我、刚刚发生了什么？
2. **任务**——登记册里有什么，单个任务内部的计划是什么？
3. **智能体**——谁能完成工作，他们被信任做什么？
4. **知识**——Aria 能读什么，内容有多新？
5. **活动**——Aria 做了什么、何时做的、结果如何？
6. **设置**——工作区如何配置？（仅作视觉参考。）

## 各界面

### 总览

问候横幅以一句话点明工作区并说明在飞任务数量；三个操作按钮位于其侧。随后是四项指标行——活动任务、等待决策、在用智能体、今日运行——每项只配一个支撑数字而非迷你图表，因为"一个数字加一行说明"比"一张带图例的图表"读得更快。之后页面分为 1.55 : 1 的两栏：宽栏承载活动任务与近期活动尾部，窄栏承载待处理列表、值守智能体与执行管线。这种不对称是刻意的——宽栏供扫读，窄栏供决策。

### 任务

四项摘要之后是带状态计数的筛选标签行、一个搜索框，以及两列卡片网格。每张卡片给出目标、当前步骤、进度线、所属工作台、时龄与参与智能体的缩写；状态徽标位于右上。选中卡片后抽屉展开，包含目标与简报、编号执行计划（标记按步骤状态着色，每步下方标注智能体与耗时）、评审结论、按类型标注的产物，以及带时间戳的事件日志。审批操作只在任务确实处于等待状态时出现在抽屉页脚。

### 智能体

名册以卡片呈现：身份、可用性圆点、摘要、至多三个能力标签、模型与指派数量。可用性筛选会统计各状态。抽屉补充模型上下文、运行次数与平均耗时、写入权限、最近活动、带成熟度的完整能力列表、当前指派（每项可跳转到任务登记册），以及该智能体的近期活动。指派按钮对其作用范围保持诚实：它只在抽屉内暂存一个标记并明说这一点，因为背后并没有可供指派的真实后端。

### 知识

左侧为集合栏，右侧为资源登记册。每个集合显示其索引状态、资源数量与密级；未被索引的集合带有一条说明，解释任务为何不能引用它。登记册逐条显示格式、来源、大小、时龄、标签、引用次数与密级。搜索在标题、来源与标签上本地匹配，分页是显式的而非无限滚动。

### 活动

按天分组的时间线。每行包含时间、结果圆点、事件标题、一行详情，以及行为者与范围。两组筛选行——范围与结果——在本地缩小列表，分组标题重复计数，任意一行可打开抽屉查看时间戳、经过时间、范围、结果、完整详情，以及指向所属任务与智能体的链接。

### 设置

导航栏中有六个分区：General、Appearance、Models、Memory、Integrations、Security。每个控件要么只读，要么只是本地状态，页面在两处说明这一点——副标题与常驻的原型提示。Appearance 分区同时充当字阶样张，这是保持字体排印诚实的最低成本方式。

## 交互模型

以下全部是本地状态。没有 API 调用、没有 `fetch`、没有 websocket，也没有超出浏览器会话的持久化。

- **导航**——导航项改变路由与哈希；侧边栏在 1024px 以下折叠为图标栏，在 720px 以下变为浮层抽屉。
- **任务详情**——从卡片或哈希打开，可用 Escape、关闭按钮或遮罩关闭，并将焦点还给打开它的元素。
- **智能体详情**——同样的契约，可从名册卡片或步骤中的智能体名打开。
- **筛选**——任务状态、智能体可用性、活动范围与活动结果各自本地筛选并显示计数；空状态总会提供返回路径。
- **搜索**——知识搜索匹配标题、来源与标签；任务搜索匹配标题、目标与工作台。
- **新建任务**——模态框校验目标非空，展示规划中状态，然后把一条演示任务插入本地状态、路由到它，并以横幅确认，横幅明确称其为演示记录。
- **反馈**——横幅可关闭，并与提示词汇一致；按钮级反馈则由按钮自身的按下与停用状态承担。
- **状态**——空、加载、错误与停用状态作为组件存在并被使用：知识登记册有未索引警告，每个筛选都有空状态，抽屉的产物与指派区块有空状态，设置中的集成行包含一条停用的连接。
- **焦点**——每个交互元素共用一个焦点环（`--aria-focus-ring`），到主区域有跳转链接，焦点顺序遵循阅读顺序。

## 响应式行为

桌面 1440px 为基准。外壳自身的断点是 1180px、1023px 与 720px；各界面在自身内容需要时另加 900、860、760、640 与 560px。导航栏在与它所映照的 DSH 框架相同的 1023px 边界折叠。在 1024px，导航栏已是紧凑态，总览在指标行以下并为单栏，卡片网格变为两列。在 720px，导航栏变为浮层抽屉，顶栏舍弃面包屑并保留系统指示、搜索与通知，筛选行改为横向滚动而非换行，指标网格变为两列，详情抽屉占满宽度。三个断点均通过 1440、1024、390 的截图以及一项报告越界元素精确位置的自动溢出探测检查；最终运行在三个宽度下的六个界面均无溢出。

## 已知限制

- **仅演示数据。** 工作区、任务、智能体、集合与活动条目都是固定装置（fixture）。会话中创建的任务存在于 React 状态中，刷新即消失；这一点在对话框、横幅与每个界面上的提示中都写明。
- **尚无宿主集成。** 原型是一个包（`AriaPrototype`），不是已注册的 DSH 插件。接入意味着把真实的会话、智能体与记忆数据映射到 `model.ts` 中的展示类型上；没有任何界面假设超出这些类型所提供的内容。
- **设置仅作视觉。** 没有任何开关会写入配置，Models、Memory 与 Security 分区刻意保持只读。
- **单一主题、单一语言。** 界面为深色与英文。令牌层可以承载浅色主题，但未定义任何浅色值，`locales/en.ts` 也是唯一字典。
- **智能体指派控件只暂存一个标记。** 它演示该交互而不伪装成后端调用；提示文案已说明这一点。
- **离线工具链。** 产出本工作的沙箱无法安装整个工作区，因此仓库级的 `pnpm typecheck`、`pnpm lint`、`pnpm test` 与 `pnpm build` 未能端到端运行。替代方案及其确切范围是：一个按仓库自身 ES2024 客户端设置配置的 TypeScript 工程，覆盖三个 Aria 包以及原子接缝所触达的每一处 `ui-primitives` 源码（0 个错误）；同样三个包经由仓库的复合项目引用构建（`packages/aria/` 0 个错误）；以严格规则集对 `packages/aria` 运行 oxlint（0 个错误）；十一个 jsdom 交互测试；以及一次 Puppeteer 截图流程。**未**验证的是仓库其余的门禁，那需要完整的依赖树。

## 未来改进

1. **接入宿主。** 把这些界面注册为 DSH 导航入口，并用会话、作业与记忆服务之上的适配层替换 `fixtures.ts`——模型类型正是为此映射而写。
2. **真实任务语义。** 原型中的任务是展示概念。真实实现需要持久化的任务记录、拥有步骤流转的调度器，以及评审闸门可以阻塞的审批路径。
3. **浅色主题。** 令牌结构已就绪，只缺取值。
4. **动效与骨架屏。** 加载状态作为组件存在，但没有界面会等待足够久以显示它们。真实数据会让它们发挥作用。
5. **以 SVG 资产发布图标套件。** 符号是共享网格上的 React 组件；导出为独立 SVG 可让桌面安装程序与文档站点共享完全相同的图形。
6. **配合辅助技术的可访问性审计。** 自动化的对比度与焦点检查通过；尚未对抽屉焦点陷阱与时间线分组执行屏幕阅读器走查。

## 运行原型

在仓库根目录、依赖已安装的情况下：

```sh
pnpm --filter @deepseek-ai/dsh-aria-prototype run preview
```

预览绑定 `0.0.0.0:5273`，无需构建步骤；它把工作区包别名到其源码。交互测试用以下命令运行：

```sh
pnpm --filter @deepseek-ai/dsh-aria-prototype exec vitest run
```
